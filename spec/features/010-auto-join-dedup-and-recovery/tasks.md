## Phase 1: Dedup — Atomic Enqueue (Problem 1)

Spec: "Problem 1 — Atomic dedup of auto-join enqueues" (`spec.md`). Design: plan.md's `insertDedupedBySourceEvent` contract and Architecture Decisions row "Dedup enforcement point".

- [x] 1.1 `packages/shared/src/db/schema.ts`: add `import { sql } from "drizzle-orm";` (not currently imported — only `drizzle-orm/pg-core` symbols are today); convert the `meetings` table from its current 2-arg `pgTable(name, columns).enableRLS()` form to the 3-arg callback-array form so it can carry the partial unique index — `pgTable("meetings", { ...unchanged columns... }, (table) => [index("meetings_source_event_unique_idx").on(table.sourceProvider, table.sourceEventId).where(sql\`${table.sourceEventId} IS NOT NULL\`)]).enableRLS()`. `index` is already imported. **Deviation:** used `uniqueIndex` (not `index`) — drizzle-orm's `index()` builder always sets `unique: false`; only `uniqueIndex()` emits `CREATE UNIQUE INDEX`. Using plain `index()` as the task literally describes would silently produce a non-unique index and defeat Problem 1 entirely. Added `uniqueIndex` to the `drizzle-orm/pg-core` import.
- [x] 1.2 `drizzle/0007_meeting_dedup_index.sql` (new file, next after `0006`): hand-written `CREATE UNIQUE INDEX "meetings_source_event_unique_idx" ON "meetings" ("source_provider", "source_event_id") WHERE "source_event_id" IS NOT NULL;` — this file is the source of truth if drizzle-kit's generated DDL for a partial unique index ever diverges from what 1.1 describes (plan.md's explicit note). **Extended per mandatory correction #2:** prepended a `DELETE ... USING` pre-dedup step (keeps the earliest row per `(source_provider, source_event_id)` pair by `(created_at, id)`, deletes the rest) so this migration doesn't fail against production data that already has the duplicates this feature fixes.
- [x] 1.3 RED+GREEN: `packages/shared/src/repositories/MeetingRepository.ts` — new `insertDedupedBySourceEvent(values: MeetingInsert): Promise<MeetingRecord>` (add `isNotNull` to the existing `drizzle-orm` import alongside `and, eq, gte, inArray`); `.insert(meetings).values(values).onConflictDoNothing({ target: [meetings.sourceProvider, meetings.sourceEventId], where: isNotNull(meetings.sourceEventId) }).returning()`; on no row, re-fetch via the existing `findBySourceEvent` and throw if still not found (conflict-reported-but-missing is a real bug, not a valid state). `claimNextPending`/`for update skip locked` stays untouched — this fixes enqueue-time duplication only.
- [x] 1.4 RED+GREEN: `packages/shared/src/services/meetingQueueService.ts` — widen `queueMeetingRun`'s return type to `Promise<{ id: string; ownerId: string }>`; source-event branch (`sourceProvider && sourceEventId && !meetingId`) replaces its `findBySourceEvent` check + later `insert` call with a single `MeetingRepository.insertDedupedBySourceEvent(...)` call, returning `{ id: record.id, ownerId: record.ownerId }`; the other 3 return points (explicit `meetingId`, manual dedupe-window hit, fresh manual insert) each add `ownerId` to their existing return object using the already-known `ownerId` param/row — no new lookups needed there.
